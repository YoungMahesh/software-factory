# Spec: Grill-with-Docs Conversational Protocol and Matt Pocock Skills in Factory Studio

Status: ready-for-agent
Triage: ready-for-agent

## Problem Statement

When building frontend applications in Factory Studio, developers currently experience an immediate, unaligned code execution loop. Whenever a user submits a chat message, Factory Studio immediately creates GitHub milestones and issues and triggers the autonomous multi-agent assembly line inside a Modal sandbox without confirming understanding.

This immediate execution introduces critical problems:
1. **Silent Assumptions & Vague Requirements**: Casual or underspecified prompts (e.g. "add analytics" or "make a dashboard") cause the Planner and Coder agents to make silent assumptions regarding architecture, layout, state management, and mock data without user validation.
2. **Untracked Architectural Decisions**: When AI models generate code, architectural choices are made implicitly in code diffs without creating or updating Architectural Decision Records (ADRs). Subsequent agent turns frequently contradict prior patterns because there is no recorded architectural memory.
3. **Missing Engineering Skills in Target Projects**: Applications generated by Factory Studio lack the repository-level documentation and engineering skills structure (`CONTEXT.md`, `docs/adr/`, `docs/agents/`, `.agents/skills/`) necessary for AI models to adhere to project-specific glossaries and constraints.
4. **Wasted Cloud Compute**: Triggering cloud sandboxes and multi-agent loops for underspecified requests wastes compute, time, and API tokens on code that the developer rejects or requests to rewrite.

## Solution

Implement the **Grill-Before-Change Protocol** in Factory Studio and establish **Target Project Skills** (including Architectural Decision Records) across all applications generated by the Software Factory:

1. **In-Studio Grilling Assistant (`factory/ui/grill.py`)**:
   Introduce a conversational reasoning service in Factory Studio that intercepts chat messages in the UI layer. When a prompt is submitted, the Grilling Assistant conducts an interactive interview using Matt Pocock's `grilling` and `domain-modeling` protocols. It asks structured question frontiers with recommended answers (`❓ Q1 ... ➡️ recommended answer`), stress-testing requirements and sharpening domain terms before code generation begins.
2. **Stateless Turn Protocol & Client History**:
   Manage conversation turns statelessly over `POST /api/studio/prompt`, passing the accumulated chat history. When in grill mode (the default), the backend returns structured question rounds without provisioning a cloud sandbox.
3. **Chat-Drafted ADR & Approval Flow**:
   When the interview settles all open questions on the frontier, the Grilling Assistant drafts a lightweight Architectural Decision Record (`docs/adr/NNNN-<slug>.md`) in markdown conforming to the domain-modeling criteria. The chat timeline displays a prominent **"Approve Plan & Build"** card. Upon user approval (or text command `/proceed`), Factory Studio commits the new ADR and updated `CONTEXT.md` to GitHub on branch `factory/<feature>`, synthesizes the GitHub issue, and dispatches the Unified Studio Sandbox assembly line.
4. **Target Project Skills Scaffolding (`factory/ui/scaffold.py`)**:
   Update `instantiate_repo_from_template` so every newly created target application is scaffolded with `CONTEXT.md`, `docs/adr/0001-tanstack-start-spa-architecture.md`, `docs/agents/`, and copies the core engineering skills (`.agents/skills/`). Supply a CLI script (`scripts/sync_target_repo_skills.py`) to sync existing test repositories.
5. **In-Sandbox ADR Quality Gate**:
   - Update Pre-flight Guard (`sandbox/factory/preflight.ts`) to require `docs/adr/` with at least one valid ADR.
   - Update Planner Agent context in `sandbox/factory/lifecycle.ts` to bundle all `docs/adr/*.md` files into the planning prompt.
   - Update Reviewer Agent (`sandbox/factory/harness.ts`) to actively verify that code changes comply with all accepted ADRs under `standardsCompliance`.
6. **Dual-Mode Prompt Composer Toggle**:
   Provide a toggle in `PromptComposer` (`[x] Grill & Align (Recommended)`) enabled by default, allowing quick bypass for trivial cosmetic fixes.

## User Stories

1. As a developer using Factory Studio, I want my feature prompts to initiate a grilling interview rather than immediately writing code, so that the AI clarifies ambiguities and aligns with my intent before implementation begins.
2. As a developer answering grilling questions, I want the questions presented in structured rounds with recommended answers, so that I can accept good defaults with a single short response.
3. As a developer with a specific architectural preference, I want to answer grilling questions with overrides, so that the assistant adapts the implementation plan to my specific constraints.
4. As a developer whose prompt uses vague terminology, I want the Grilling Assistant to sharpen my terminology against `CONTEXT.md`, so that domain concepts remain precise.
5. As a developer whose requirements introduce an architectural trade-off, I want the Grilling Assistant to draft an Architectural Decision Record (ADR) directly in the chat, so that the decision is documented before any code is generated.
6. As a developer reviewing a completed interview, I want to see a clear "Approve Plan & Build" card in the chat timeline with the draft ADR preview, so that I have explicit control over when cloud execution begins.
7. As a developer ready to proceed, I want clicking "Approve Plan & Build" (or typing "/proceed") to commit the ADR to Git and launch the assembly line, so that execution is seamless.
8. As a developer making a trivial cosmetic fix (e.g. changing button color), I want to uncheck "Grill & Align" in the composer, so that simple changes can build immediately without interview overhead.
9. As a developer creating a new application in Factory Studio, I want the generated repository to automatically include `CONTEXT.md`, `docs/adr/`, `docs/agents/`, and `.agents/skills/`, so that my new project is self-documenting and agent-ready from day one.
10. As an operator maintaining existing test repositories, I want a sync CLI utility to backfill Matt Pocock skills and ADR layouts across all existing repositories in the test organization, so that legacy repos remain consistent.
11. As a developer watching the assembly line execute, I want the Planner Agent to read all accepted ADRs, so that the generated plan respects existing architectural decisions.
12. As a developer reviewing agent work, I want the Reviewer Agent to reject code changes that violate accepted ADRs, so that the quality gate prevents architectural drift.
13. As a developer working in Factory Studio, I want grilling turns to respond in under a second without spinning up a 30-minute cloud sandbox, so that conversational turns are fast and cost-effective.
14. As an automated test runner, I want the Grilling Assistant to support deterministic mock responses, so that backend test suites can verify interview flows offline without live API credentials.
15. As a developer refreshing the browser during an interview, I want my chat history and unsettled question rounds to remain intact, so that I don't lose my conversation progress.

## Implementation Decisions

- **In-Studio Grilling Assistant Service**:
  Create `factory/ui/grill.py` providing `GrillingAssistant`. It connects to OpenCode Go (`https://api.opencode.net/v1`) using `OPENCODE_GO_API_KEY` (ephemerally resolved from `~/.config/opencode/opencode.env` or decrypted from `secrets/opencode.env`). It embeds system instructions derived from `grilling/SKILL.md` and `domain-modeling/SKILL.md`, outputting structured JSON responses:
  - `{ "type": "grill_round", "round": number, "questions": [...], "draft_adr": null, "summary": string }`
  - `{ "type": "ready_for_approval", "plan": string, "draft_adr": { "title": string, "filename": string, "content": string }, "summary": string }`
  Includes mock mode when `OPENCODE_GO_API_KEY` is not present or when testing.

- **FastAPI Endpoint Contracts in `factory/ui/app.py`**:
  - `POST /api/studio/prompt`:
    - Accepts `{ "repo": string, "prompt": string, "grill": bool, "history": ChatMessage[], "model": string }`.
    - If `grill` is true (default), invokes `GrillingAssistant` and returns `{ "accepted": true, "turn": GrillTurnResult }`.
    - If `grill` is false, runs the fast intent guard and immediately dispatches the job (legacy/fast-build behavior).
  - `POST /api/studio/approve`:
    - Accepts `{ "repo": string, "milestone_title": string, "prompt": string, "draft_adr": { "filename": string, "content": string }, "context_update": string | null, "model": string }`.
    - Commits the ADR file (e.g. `docs/adr/0002-<slug>.md`) and any `CONTEXT.md` updates directly to GitHub on `factory/<feature>` branch via GitHub API using organization credentials.
    - Resolves/creates milestone, creates issue, provisions/ensures Unified Studio Sandbox, creates and starts the assembly line job in `JobRegistry`.

- **Target Project Scaffolding in `factory/ui/scaffold.py`**:
  Provide `scaffold_target_repo(repo_name, token, org)` which commits:
  - `CONTEXT.md` (initial domain glossary for the TanStack Start app).
  - `docs/adr/0001-tanstack-start-spa-architecture.md` (canonical baseline architecture ADR).
  - `docs/agents/domain.md`, `docs/agents/issue-tracker.md`, `docs/agents/triage-labels.md`.
  - `.agents/skills/` (the core engineering skills copied from `shared/target_template_skills/` or `.agents/skills/`).
  Integrate this directly into `instantiate_repo_from_template` in `factory/ui/github.py` after repo generation.
  Provide `scripts/sync_target_repo_skills.py` for batch upgrading existing repositories.

- **In-Sandbox Pre-flight and Reviewer Enforcement**:
  - In `sandbox/factory/preflight.ts`: `assertPreflightAsync` verifies that `docs/adr/` exists and contains at least one `.md` file.
  - In `sandbox/factory/lifecycle.ts`: Load all `docs/adr/*.md` files from the workspace into an `adrsContent` bundle and provide it to `plannerRunner`.
  - In `sandbox/factory/harness.ts`: Update `REVIEWER_SYSTEM_PROMPT` to state that `standardsCompliance` must verify that code changes adhere strictly to `docs/adr/*.md` records.

- **Frontend Studio UI Enhancements**:
  - In `factory/ui/frontend/src/components/PromptComposer.tsx`: Add a checkbox toggle `[x] Grill & Align` defaulting to `true`.
  - In `factory/ui/frontend/src/views/StudioView.tsx`: Render assistant grilling round cards with formatted question blocks and badges.
  - Add `ApprovalCard.tsx` in `factory/ui/frontend/src/components/`: Displays the finalized plan summary, expandable draft ADR markdown, and an **"Approve Plan & Build"** primary button.
  - In `factory/ui/frontend/src/App.tsx` and `api.ts`: Wire up the turn cycle and approval mutation.

## Testing Decisions

- **What makes a good test**: Tests must verify observable behavior at the highest public boundaries without asserting private implementation details.
- **Backend API Boundary (`tests/test_ui.py`)**:
  - Test `POST /api/studio/prompt` in grill mode returning a `grill_round` response with structured questions and recommended answers without spawning containers.
  - Test `POST /api/studio/prompt` with history reaching `ready_for_approval` containing a formatted draft ADR.
  - Test `POST /api/studio/approve` committing the ADR to GitHub API, creating the issue, and starting the assembly line job.
  - Test `instantiate_repo_from_template` invoking target repository scaffolding.
- **Frontend Integration Boundary (`factory/ui/frontend/src/views/StudioView.test.tsx` & `App.test.tsx`)**:
  - Test toggling the "Grill & Align" mode in `PromptComposer`.
  - Test rendering assistant grilling rounds and recommended answers.
  - Test rendering the "Approve Plan & Build" card and clicking approve triggering the build API call.
- **In-Sandbox Pipeline Boundary (`sandbox/factory/preflight.test.ts` & `pipeline.test.ts`)**:
  - Test `assertPreflightAsync` passing when `docs/adr/` contains valid ADRs, and failing when `docs/adr/` is missing.
  - Test `runPlannerAgent` and `runReviewerAgent` receiving the bundled ADR context.

## Out of Scope

- Audio or speech-to-text grilling interfaces.
- Interactive multi-user grilling sessions (pair interviewing).
- Automatic git merging of draft pull requests without human review.
- Custom external issue tracker providers beyond GitHub Issues and Local Markdown.

## Further Notes

- Adheres strictly to ADR 0034 (Factory Studio), ADR 0038 (Unified Studio Sandbox), and ADR 0040 (Grill-with-Docs and Matt Pocock Skills in Factory Studio).
- All domain terminology conforms to `CONTEXT.md`.
