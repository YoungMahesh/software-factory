# Encryption in Transit for Remote PostgreSQL Connections

To securely support client applications connecting from remote servers across untrusted networks, the PostgreSQL container enforces TLS (`hostssl`) for all remote TCP connections while preserving unencrypted loopback access for the local control plane. During bootstrap, the control plane generates an internal Root CA and issues a server certificate with Subject Alternative Names matching the configured `PUBLIC_POSTGRES_HOST`, `localhost`, and `127.0.0.1`, automatically regenerating the server certificate if the public host changes. Generated client connection strings mandate full certificate and hostname verification (`?sslmode=verify-full&sslrootcert=ca.crt`), and the root CA certificate is exposed via an unauthenticated endpoint (`/api/ca.crt`), dashboard credentials affordances, and MCP tools for seamless automated provisioning.
