# 0062: Clean Canvas Invariant and Template Boilerplate Purge

**Status**: Accepted

To ensure that applications generated by Factory Studio provide an unencumbered, production-ready user interface from the very first conversational turn, we established the **Clean Canvas Invariant** across the Canonical Template Repository, Assembly Line Agent prompts, ticket synthesis, and reviewer quality gates.

## Context

When developers prompted Factory Studio to create a new application (e.g. creating a counter or calculator app), the newly provisioned project inherited starter boilerplate from the canonical template repository (`software-factory-09-test/tanstack-start-template`):
- A placeholder hero banner in `src/routes/index.tsx` displaying "Application Workspace" and "Ready for development. Prompt Factory Studio to build features and components."
- A default framework branding badge in `src/components/Header.tsx` displaying "TanStack Start".

Autonomous assembly line agents (the Planner Agent and Coder Agent) frequently mounted newly generated UI components directly beneath or inside the placeholder container rather than replacing it. Furthermore, the Reviewer Agent did not flag or reject pull requests that retained this starter copy. Consequently, newly minted web applications presented visible development chrome and boilerplate copy unrelated to the target application domain.

## Decision

We instituted defense-in-depth enforcement of the **Clean Canvas Invariant** across four layers of the system:

1. **Canonical Template Repository Purge**:
   - Updated `src/routes/index.tsx` in `software-factory-09-test/tanstack-start-template` to render an empty, clean main container canvas (`<main className="page-wrap px-4 py-8 min-h-screen"></main>`) devoid of placeholder cards, guide copy, or promotional text.
   - Updated `src/components/Header.tsx` default brand badge from "TanStack Start" to a neutral "App" baseline.
   - Committed and pushed these updates directly to `main` on `software-factory-09-test/tanstack-start-template`.

2. **Assembly Line Prompts Defense-in-Depth**:
   - **Planner Agent (`sandbox/factory/harness/prompts/planner_system.md`)**: Added an explicit Clean Canvas Invariant section instructing the Planner to inspect route components and header chrome for starter boilerplate and mandate their complete replacement in implementation plans.
   - **Coder Agent (`sandbox/factory/harness/prompts/coder_system.md`)**: Instructed the Coder to overwrite starter placeholder cards in `src/routes/index.tsx` and customize the header brand in `src/components/Header.tsx` rather than appending new UI components below placeholder cards.
   - **Reviewer Agent (`sandbox/factory/harness/prompts/reviewer_system.md`)**: Mandated that `standardsCompliance` inspects git diffs for retained starter boilerplate copy ("Application Workspace", "Ready for development", etc.) and rejects (`verdict: "rejected"`) pull requests with blocker severity if found.

3. **Factory Studio Ticket Synthesis**:
   - Updated `synthesize_ticket_content` in `factory/ui/github/_issues.py` to automatically include acceptance criteria for initial feature tickets:
     - `Replace default starter template placeholder markup in src/routes/index.tsx with the new application UI.`
     - `Update the header brand in src/components/Header.tsx to display the application title.`

4. **Domain Modeling**:
   - Formalized `Clean Canvas Invariant` in [`CONTEXT.md`](../../CONTEXT.md) with explicit terminology boundaries.

## Consequences

- Newly generated web applications in Factory Studio start on an empty canvas with neutral branding, immediately reflecting the user's prompt without leftover development workspace chrome.
- Coder and Planner agents are explicitly guided to overwrite starter markup instead of nesting components below template cards.
- The Reviewer Agent quality gate actively blocks regressions from merging into target repositories.
- Zero extra network roundtrips or runtime dependencies are introduced.
